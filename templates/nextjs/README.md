# Midtrans Integration — Next.js (App Router) Template

Generated by **midtrans-kit** (`midtrans init nextjs`).

## What you get

```
lib/midtrans.ts                     dependency-free Midtrans client
lib/prices.ts                       SERVER-SIDE price catalog (edit me!)
lib/orders.ts                       order ledger (in-memory → swap for a DB)
app/api/payment/create/route.ts     checkout: price → register → Snap token
app/api/payment/webhook/route.ts    notification handler (signature-verified)
app/api/payment/status/route.ts     order status + webhook-fallback reconcile
components/pay-button.tsx           drop-in checkout button
.env.example                        env template
```

## Setup

1. Copy these files into your Next.js App Router project (`src/` layout works too —
   adjust the `@/lib/...` imports if you don't use the `@/*` alias).
2. `cp .env.example .env.local` and fill in your keys from the Midtrans dashboard
   (Settings → Configuration → Access Keys). Sandbox keys start with `SB-Mid-`.
3. Edit `lib/prices.ts` with your products.

## Try it

```bash
npm run dev
# put <PayButton itemId="tshirt" label="Buy T-shirt (Rp 50.000)" /> on a page
```

Sandbox payment: card `4811 1111 1111 1114`, CVV `123`, OTP `112233`.

## Test the webhook locally (no tunnels needed)

```bash
midtrans webhook:test --status settlement --url http://localhost:3000/api/payment/webhook
midtrans webhook:test --status expire     --url http://localhost:3000/api/payment/webhook
midtrans webhook:test --tamper            --url http://localhost:3000/api/payment/webhook  # must 403!
```

Note: `webhook:test` generates its own `TEST-…` order ids, so the ledger will
answer `"ledger":"unknown"` — expected. To test the full paid path, pay a real
sandbox order created by the PayButton, or pass `--order-id` of a pending order.

## Going live — checklist

- [ ] Production keys (`Mid-server-…`) in env, both `IS_PRODUCTION` flags `true`
- [ ] Payment Notification URL registered in the Midtrans dashboard:
      `https://your-domain.com/api/payment/webhook`
- [ ] `lib/orders.ts` swapped to a database (keep the same function contract)
- [ ] Idempotency: unique constraint on `order_id`, settle only moves forward
- [ ] Verify amounts at settle time (the template already does — keep it)
